# 公网个人应用的 SSH 与登录防护加固

## 流程
1. 盘点实际暴露端口、鉴权、权限与证书，不把加密视为完整应用防护。
2. 收紧本机凭证文件权限。新增专用 SSH 公钥时保留原密钥，先验证独立密钥登录，再修改密码认证策略；配置语法和有效值检查后 reload，并重新独立连接。
3. 为目标站点设置请求速率、突发与并发上限，给初次静态资源加载、轮询和媒体请求保留余量，超限使用明确状态码。
4. 仅记录失败认证所需的来源、时间和状态，避免记录授权头；用 Fail2ban 监测可验证的失败日志。
5. 多站点服务器优先采用目标站点内的封禁动作，避免按整机 HTTPS 端口封禁而误伤其他网站及管理连接。文件更新应加锁、原子替换、校验并支持失败回滚。
6. 若限制控制端口新连接，验证客户端重连与正常流量仍可用。修改 UFW 规则后检查有效规则，不能假定先前 ALLOW 已移除。
7. 验证自动触发、实际拒绝、解封和正常访问恢复；最后测试浏览器登录、真实播放和进度跳转。移除测试封禁。

## 验证与限制
本次按 20 请求/秒、突发 80、来源并发 16 设置音乐站点，10 分钟 12 次失败封禁 15 分钟；这些是本次负载参数，不应直接复制到所有应用。浏览器 Basic 认证首次挑战也可能产生 401，需要给正常操作留余量。

关闭 root 密码登录后应向用户说明新的管理入口及密钥保管要求。不能未经验证就移除旧登录方式。限流和失败封禁不解决密码泄露、应用漏洞或上游流量攻击；VPN/多因素身份网关属于另外的接入变更。
