# 项目修改记录维护规则

适用：项目代码、样式、配置和文档修改完成后维护修改台账。来源为 [[sources/2026-11-18-web-front修改记录规则]]；执行证据见 [[runs/2026-11-18-修改记录规则同步Obsidian]]。项目的 `AGENTS.md` 是实际执行依据；其他项目采用前需结合其约定，不自动覆盖项目规则。

## 输入与输出

- 输入：实际修改文件、完成时间、关键差异、执行过的验证及未验证事项。
- 输出：项目 `docs/修改优化记录.md` 的新条目，必要时附 `docs/YYYY-MM-DD-主题.md` 详细文档。

## 执行规则

1. 每次代码、样式、配置或文档实质修改都同步更新台账；仅分析且未写文件时无需记录。
2. 标题采用 `### YYYY-MM-DD HH:mm 修改主题`，时间为北京时间，以实际完成时间为准。
3. 条目按时间倒序，最新放在说明后；同日也倒序。
4. 历史仅知日期时保留日期并标注“具体时间未记录”，同日按原记录先后倒排，不补造时间。
5. 记录原因、具体文件路径、最终行为、验证结果与待确认事项。
6. 正文附关键修改代码，优先用 diff 展示前后；新增代码可用相应语言块。文档、配置也展示关键片段，不复制整份文件；无法核实的历史差异不补造。
7. 连续微调合并条目，更新为最后完成时间并重新排序，保留必要变更过程；独立修改另建条目。
8. 跨模块或较复杂变更另写详细文档，从台账链接，避免重复大段内容。
9. 只写实际验证结果，明确未执行的检查；禁止记录密钥、令牌和敏感业务数据。
10. 台账自身更新不递归记账；规则文档实质修改仍记录一次。

## 条目模板

````markdown
### YYYY-MM-DD HH:mm 修改主题

- 原因：问题或需求。
- 范围：具体文件路径。
- 结果：最终行为及限制。
- 验证：实际执行结果、未执行检查和待确认事项。
- 详细说明：[详细文档](相对路径)（可选）。
- 修改代码：`文件路径`

```diff
-修改前关键内容
+修改后关键内容
```
````

## 验证与失败处理

- 检查排序、文件路径和链接、关键差异与实际修改的一致性、历史正文保留及 UTF-8 无 BOM。
- 对项目差异运行 `git diff --check`；业务验证按实际变更执行，文档检查不能替代构建或浏览器验证。
- 若缺少历史时间或代码证据，保留未知状态；若目标项目已有不同规则，先遵循该项目约定。
- 本流程经 web-front 规则和台账整理验证；跨项目推广尚未验证，不表示自动执行或自动同步。
