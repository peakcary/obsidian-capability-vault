# 项目协作约定

## 修改记录

- 每次完成代码、样式、配置或文档的修改、优化、改进，必须同步更新 `docs/修改优化记录.md`，作为统一修改总台账。
- 每条记录标题使用 `### YYYY-MM-DD HH:mm 修改主题`，时间采用北京时间（Asia/Shanghai），以实际完成时间为准。
- 全部条目按时间倒序排列，最新记录置于台账说明之后；同日记录也按时间倒序，保留既有历史。历史记录仅知日期时使用 `### YYYY-MM-DD 修改主题（具体时间未记录）`，不得补造时分，同日沿用原记录的先后关系倒排。
- 记录修改原因、涉及文件或模块、最终行为、实际验证结果及待确认事项。正文必须列出修改文件路径，并附关键代码差异，优先使用 `diff` 代码块说明修改前后；新增内容可用对应语言代码块，删除内容可用 diff。文档或配置修改同样记录关键片段，不复制整份文件。历史条目缺少可核实差异时保留原记录，不将当前代码冒充历史改动。
- 简单修改直接在总台账说明；跨模块、行为变化较大、需要说明方案取舍或迁移步骤的修改，另外编写详细文档，并从台账链接到该文档。
- 详细文档存放在 `docs/`，命名优先使用 `YYYY-MM-DD-主题.md`；沿用已有相关文档时可以直接更新，不重复建档。
- 同一任务的连续微调合并记录，更新标题为最后完成时间并移至对应倒序位置，保留必要的变更过程；后续独立修改新增条目，不覆盖历史结论。
- 总台账负责摘要和索引，详细文档承载实现、取舍及验收细节，避免大段重复。
- 验证只记录实际执行结果；未执行的构建、测试、浏览器或移动端检查必须明确注明，不能写为通过。
- 只分析且未修改文件时，无需追加记录；分析结果保存为文档时需记录。
- 不记录密钥、令牌或敏感业务数据。不要求每次任务补录全部历史文档。
- 更新台账本身无需再创建递归记录；本约定或其他文档的实质修改仍需记录一次。

- 详细说明：[文档标题](相对路径)（有详细文档时填写）。
- 修改代码：逐个列出文件路径和关键差异；较长差异放详细文档并链接。
