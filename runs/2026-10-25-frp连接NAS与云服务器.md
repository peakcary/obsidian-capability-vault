# frp 连接 NAS 与云服务器

## 请求与范围
用户授权读取本机连接配置，通过其云服务器提供 NAS 应用外网访问。首个目标为已部署的音乐播放器；项目看板尚未部署。

## 执行摘要
- 检查云服务器已有 Nginx、HTTPS、主机防火墙及端口，不覆盖已有站点。
- 下载 frp 0.71.1 的 AMD64 与 ARM64 官方发布包，核对官方 SHA-256。
- 云端安装独立普通用户的 systemd frps 服务，配置独立 token、强制 TLS 与客户端证书信任校验；业务映射仅回环监听。
- NAS 准备 scratch 客户端镜像和 Docker Compose；配置只读，采用 host 网络访问现有音乐服务。
- 已有拟用子域 DNS 指向云服务器，配置独立 Nginx 入口与公网证书，续期由 Certbot 及 reload hook 处理。
- 用临时 NAS 客户端完成端到端试运行后停止，等待用户输入 sudo 密码启动长期客户端容器。

## 验证
两端配置语法、控制连接、代理注册、公网 HTTPS、拒绝未认证请求、登录后网页/API、实际歌曲 Range、浏览器播放与跳转均通过。未把临时进程试运行误报为持久容器完成。

## 教训与限制
- 系统代理设置不一定被 curl 使用；本次直接下载超时，显式使用本机代理后成功，并以官方校验和验证产物。
- 临时客户端退出后代理端口关闭，必须区分隧道配置完成与长期客户端已启动。
- NAS SSH 自动关闭与 Docker 生命周期无关；部署需及时确认 SSH 状态。
- 云端 HTTPS 自动续期与隧道自建证书是两个证书生命周期，后者需要另行安排更新。
- 不记录连接密码、令牌、私钥或媒体内容。

## 产物
本机用户项目的 frp-deploy 目录保存配置生成脚本、部署脚本及 README；NAS 保存客户端部署包，云服务器保存服务和独立站点。
