# Wails播放器增加NAS网页模式

## 请求与范围
保留 Go/Wails 桌面播放器，增加可在 ARM64 NAS 上运行的网页服务及 Docker 部署方式。

## 执行与产物
- 通过 build tag 隔离 GUI 生命周期、原生窗口、平台代码和 Objective-C 文件，保留共享曲库、媒体服务及歌词逻辑。
- 网页提供限定方法的 HTTP API、受挂载根目录约束的文件夹选择器、同源音频 URL 和 Range 服务。
- 音乐只读，歌词缓存与曲库独立持久化；网页登录与来源检查覆盖接口及静态资源。
- 提供常规多阶段 Dockerfile，以及静态 ARM64 程序加公开 CA 证书的 scratch 离线构建方案。
- 部署包上传用户 NAS，Compose 配置校验成功；用户本机交互输入 sudo 密码后完成镜像构建及容器启动。

## 验证
- 桌面与 web 构建均通过 Go 竞态测试；web 通过 vet。
- 网页实测登录、目录选择、导入、合成 WAV 播放、拖动、同步歌词、刷新恢复和移动尺寸。
- 原桌面播放器、经典界面、独立窗口迁移、队列等四组浏览器回归通过。
- 原生 ARM64 程序在 NAS 上通过登录、真实歌曲导入、Range 和歌词 API 测试；未把原生程序测试误报为容器验收。
- 实际容器健康接口返回 200；未认证请求返回 401。浏览器使用实际 NAS 音乐验证播放、跳转、歌词接口、刷新恢复和移动端目录弹窗。
- 通过宿主机 /proc 核实进程 UID 为普通用户，音乐挂载为 ro、数据为 rw；确认曲库 JSON 已保存。未执行容器重启测试。

## 失败与经验
- 排除桌面 Go 文件时必须合并已有 build 表达式，并处理 Objective-C 文件；重复 go:build 会导致编译失败。
- 桌面媒体地址绑定本机回环，网页必须转换为同源代理路径并调整 media-src。
- 前端 iframe 可能调用父窗口绑定；文件夹弹窗实际出现在父页面，UI 测试需定位正确文档。
- 此 NAS 的 SFTP 与 SSH shell 可见路径不一致，rsync 也受限制；改用 SSH tar 上传，公开证书通过 SSH 读取。
- 工具链下载失败时，使用官方可达镜像并对照官方 SHA-256 校验。
