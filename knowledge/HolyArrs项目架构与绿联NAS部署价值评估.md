# HolyArrs 项目架构与绿联 NAS 部署价值评估

## 结论与适用条件

现有绿联 NAS 从架构和历史硬件配置看适合运行 HolyArrs。部署价值取决于是否需要自动追剧、找片、请求审批和下载后归档。当前主要使用照片整理与现有音乐播放时，新增收益有限；建议先完成现有媒体中心持久部署、重启恢复和备份验收，再按实际影视需求试点。

这是候选方案评估，不代表用户已决定部署，也不代表 NAS 当前资源充足或服务在线。评估整理于 2026-11-18；NAS 状态依据既有记录，其中媒体中心最新相关记录到 2026-11-15，没有连接设备复核。

## 项目定位与架构

HolyArrs 将影视、音乐、请求审批、资源搜索、质量评分、下载调度和入库管理整合到一个应用。主要流程：浏览与请求 → 审批 → 搜索资源 → 评分选择 → 外部下载器 → 导入媒体库 → 通知媒体服务器。

| 部分 | 实现与含义 |
| --- | --- |
| 后端 | Go 模块化单体，模块通过接口与装配代码协作 |
| 前端 | Svelte 5、SvelteKit、TypeScript、Vite，静态产物嵌入 Go 程序 |
| 数据 | SQLite，主业务库与事件历史库分离 |
| 发布 | 单程序、scratch 容器、ARM64 镜像，默认端口 6262 |
| 工程约束 | 模块依赖分层、SQL 表归属与统一外部请求出口，有结构检查 |
| 运维 | 健康检查、诊断、备份恢复、安全模式及运行降权 |

项目整合的是媒体自动化工作流。“替代多个 Arr 应用”不等于与每个应用功能完全等价。下载仍需外部下载器；播放端和资源来源也需要单独配置。默认元数据服务由作者提供，自托管不等于完全离线独立。

本地静态分析未启动服务或运行完整测试。测试文件数量和 README 的资源数据不能替代实际可靠性、覆盖率或性能验证。

## NAS 适配依据

既有巡检记录：绿联 DH4300 Plus、RK3588 八核 ARM64、约 8GB 内存、UGOS/Debian，有 ARM64 Docker 应用运行经验。HolyArrs 提供 ARM64 镜像，技术路线匹配。当前内存、磁盘容量、端口及 Docker 状态仍需实查。

可复用条件：`/volume1/docker` 应用目录、既有普通用户身份 `1000:10`、frp/Nginx/HTTPS 链路与媒体目录管理经验。目录读写权限应逐个验证，不能从已有音乐权限推定其他目录可写。

参见 [[knowledge/NAS个人应用平台建设全流程与知识总览]]、[[runs/2026-10-25-NAS SSH连接与只读巡检]]。

| 需求 | 适合承担的应用 | HolyArrs 增益 |

## 部署前需要解决的边界

- 下载器、资源来源、播放端：确认已有服务、API 兼容性、网络连通及实际资源可用性。HolyArrs 官方明确不自行下载。
- 数据目录：配置与 SQLite 放本地磁盘，不能放网络共享；建议独立 `/volume1/docker/holyarrs`。
- 文件路径：下载器和 HolyArrs 尽量采用一致的路径与同一父目录挂载；不同挂载可能导致完整复制，路径不一致会导致导入失败。
- 文件所有权：按实际 UID/GID 和 ACL 配置，避免递归改权限；首次试点使用独立影视目录，不直接整理已有音乐库。
- 并发管理：避免 HolyArrs 与 media-hub 同时移动或重命名同一批文件。
- 备份：数据库、配置、媒体文件及主密钥分别考虑。普通备份不含 `holyarrs.key`，需独立保存。历史记录为单数据盘，不能视为已有镜像冗余。
- 访问：首次部署控制访问范围，首个创建账户者可成为所有者。先内网试用，需要外网时再复用 HTTPS 链路并验证认证。
- 元数据依赖：实测 NAS 到默认元数据服务的连通与体验，需要时评估自有密钥或服务配置。

## 建议的最小试点与验收

以下是未执行的建议，不是已验证部署流程：

1. 只读核实当前 NAS 资源、目录、端口、Docker 及已有下载器和媒体服务器。
2. 固定选定镜像版本，创建独立配置和测试影视目录，先在内网创建所有者账户。
3. 接一个下载器和一个可用资源来源，以可合法获取的测试内容验证请求、搜索、评分、下载、入库和播放链路。
4. 检查路径一致性、复制或移动行为、目录权限和失败重试，确认不影响现有媒体。
5. 验证容器重建持久化、NAS 重启恢复、数据库与密钥恢复；有明确使用收益后再接正式影视目录。

既有媒体中心截至相关记录仍为原生 Python 服务，Docker 激活和设备重启恢复未验收。2026-11-15 最终待激活归档与文档同步曾因 SSH 关闭未完成；后续以最新执行记录和实机为准，不能直接用旧归档覆盖当前服务。
