# 绿联客户端内播放器采用原生UPK适配路线

## 决策
针对“在绿联客户端内部窗口打开”的需求，推荐复用纯 Go 服务制作原生 UPK，使用 inner 与官方鉴权通路；现有 Docker 网页版作为独立的浏览器运行方式保留。

## 理由
目标设备上 Docker 入口实测跳出浏览器，官方 Docker 应用模板也采用 tab。原生应用具有明确的静态资源、网关、独立用户和共享目录授权机制，适合当前无外部数据库或复杂容器依赖的 Go 播放器。

## 前提与未决
需要官方设备开发者授权、原生接口和音频鉴权适配、Linux 打包环境以及真实客户端验收。此决策是技术建议，不表示原生部署完成，也不据此关闭旧服务。
